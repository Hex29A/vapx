vapx

CLIMCP

Let an AI assistant look at and operate your Axis cameras. vapx mcp is a Model Context Protocol server built into vapx; it reads the same cameras.yaml as the command line, so there is nothing more to configure.

You need vapx on the machine that runs your assistant (see install) and at least one camera added with vapx config add.

Claude Code

claude mcp add vapx -- vapx mcp

Claude Desktop and other stdio clients

Add this to the client's MCP configuration. The client starts vapx itself.

{ "mcpServers": { "vapx": { "command": "vapx", "args": ["mcp"] } } }

Over HTTP

For a client on another machine, or a server that keeps running. HTTP needs a token: paste a long random string when asked (for example from openssl rand -hex 32).

read -rs VAPX_MCP_TOKEN && export VAPX_MCP_TOKEN vapx mcp --transport http --bind 127.0.0.1:8080

Then point the client at it, with the same token in the header:

{ "mcpServers": { "vapx": { "type": "http", "url": "http://127.0.0.1:8080/mcp", "headers": { "Authorization": "Bearer " } } } }

Things to ask

  • Take a snapshot from every camera.
  • Which cameras run outdated firmware?
  • Move the PTZ camera to its home position.
  • Are all my cameras online, and how warm are they?
  • Compare the settings of two cameras and show what differs.

Safety

Tools that change a camera are marked as such, so your client can ask before it runs one; a firmware upgrade also needs an explicit confirmation. Passwords, users and network settings cannot be changed through MCP, and parameter values that look like secrets are shown as redacted. The HTTP server refuses requests without the token.
